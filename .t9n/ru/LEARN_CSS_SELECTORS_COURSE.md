# Селекторы CSS

> Курс 4 из программы. Для тех, кто прошёл [Введение в CSS](LEARN_CSS_INTRODUCTION_COURSE.md) и
> знает, что правило — это селектор и блок объявлений. Здесь — весь язык селекторов: от `p` до
> `:has()`, со специфичностью каждой части и с тем, как браузер на самом деле их проверяет.

**Что вы будете понимать после курса**

- грамматику селектора: простой, составной, сложный селектор и список селекторов;
- все виды простых селекторов, включая шесть операторов атрибутов и флаги `i` и `s`;
- четыре комбинатора и почему «родительского селектора» не было двадцать лет;
- `:is()`, `:where()`, `:not()`, `:has()` и их специфичность;
- как считать специфичность любого селектора без ошибок;
- почему браузер читает селектор справа налево и какие «правила производительности» — мифы.

## 1. Грамматика: из чего собран селектор

Селектор — **шаблон над деревом**: для каждого элемента он отвечает «подходит» или «нет». Спецификация
(Selectors Level 4) строит его из четырёх уровней:

| Уровень | Английский | Пример | Смысл |
|---|---|---|---|
| простой селектор | simple selector | `a`, `.btn`, `#top`, `[href]`, `:hover` | одно условие |
| составной | compound selector | `a.btn[href]:hover` | несколько условий **на одном** элементе, без пробелов |
| сложный | complex selector | `nav > ul a.btn` | составные, связанные **комбинаторами** |
| список | selector list | `h1, h2, .title` | любой из сложных |

В составном селекторе селектор типа (или `*`) может быть только **первым**: `a.btn` верно, `.btn a`
— уже другой, сложный селектор (с комбинатором-пробелом), а `.btna` — просто класс `btna`.

Пробел значим: `div.note` — div с классом note; `div .note` — элемент с классом note **внутри** div.

## 2. Селекторы типа, универсальный, класса и id

### 2.1. Тип и `*`

`p` выбирает все элементы `p`. В HTML-документе имя типа не зависит от регистра (`P` = `p`); в SVG
внутри HTML и в XML — зависит (`foreignObject`).

`*` — **универсальный селектор**: любой элемент. В составном селекторе он подразумевается: `.btn` —
то же, что `*.btn`. Специфичность `*` — ноль.

### 2.2. Класс

`.note` подходит элементу, у которого в атрибуте `class` среди слов, разделённых пробелами, есть
`note`. Регистр важен (в режиме стандартов): `.Note` не подходит к `class="note"`.

Классы — главный инструмент авторского CSS: их можно повесить на любой элемент, их много на одном
элементе, и они задают **смысловую роль**, а не положение в дереве.

### 2.3. Id

`#top` подходит элементу с `id="top"`. Id должен быть уникален в документе, но браузер этого не
проверяет: если id повторяется, CSS-селектор `#top` подойдёт всем, а `getElementById` вернёт
первый.

Id имеет огромную специфичность (раздел 8), поэтому в стилях его обычно избегают: правило с `#id`
трудно перебить. Id нужен для якорей (`href="#top"`), связи `label`↔`input`, ARIA и JavaScript.
Если стилизовать по id всё же нужно, но без веса, есть приём `[id="top"]` — это селектор атрибута,
он весит как класс.

Экранирование: имя класса или id, начинающееся с цифры, требует экранирования: `#\31 23` для
`id="123"`. В JavaScript для этого есть `CSS.escape('123')`.

## 3. Селекторы атрибутов

### 3.1. Семь форм

| Селектор | Подходит, если атрибут… | Пример |
|---|---|---|
| `[attr]` | присутствует, с любым значением (даже пустым) | `[disabled]` |
| `[attr="v"]` | равен `v` целиком | `[type="email"]` |
| `[attr~="v"]` | содержит **слово** `v` в списке через пробелы | `[rel~="noopener"]` |
| `[attr\|="v"]` | равен `v` или начинается с `v-` | `[lang\|="en"]` → `en`, `en-GB` |
| `[attr^="v"]` | начинается с `v` | `[href^="https:"]` |
| `[attr$="v"]` | заканчивается на `v` | `[href$=".pdf"]` |
| `[attr*="v"]` | содержит подстроку `v` | `[href*="example"]` |

Подробности, которые отличают знание от догадки:

- `.note` — это ровно `[class~="note"]`, только короче и быстрее.
- `|=` придуман для языковых кодов. Для проверки языка элемента лучше `:lang(en)`: он учитывает
  язык, **унаследованный** от предков, а `[lang|="en"]` видит только атрибут на самом элементе.
- `^=`, `$=`, `*=` с пустой строкой (`[href^=""]`) не подходят **ничему** — так определено в
  спецификации.
- Значение можно писать без кавычек, если это корректный идентификатор: `[type=email]`. Кавычки
  обязательны для пробелов, точек и начальных цифр: `[href$=".pdf"]`.

### 3.2. Флаги `i` и `s`

Регистр значений атрибутов по умолчанию **важен**, но в HTML для ряда исторических атрибутов
(`type`, `lang`, `dir`, `align` и др.) спецификация HTML делает сравнение нечувствительным к
регистру. Флаги управляют этим явно:

```css
a[href$=".pdf" i]   { }   /* .pdf, .PDF, .Pdf */
input[type="text" s] { }  /* только строчное text */
```

`i` поддерживается всеми браузерами. `s` поддержан не везде, поэтому полагаться на него в рабочем
коде рано.

## 4. Комбинаторы

| Комбинатор | Запись | Читается | Подходит `B`, если… |
|---|---|---|---|
| потомок | `A B` | B внутри A | у B есть **предок** A (на любой глубине) |
| ребёнок | `A > B` | B — ребёнок A | **родитель** B — это A |
| соседний | `A + B` | B сразу после A | **предыдущий брат-элемент** B — это A |
| последующий | `A ~ B` | B где-то после A | среди **предыдущих братьев** B есть A |

Главное ограничение, которое было в CSS до `:has()`: все комбинаторы смотрят **вверх или назад**
по дереву от выбираемого элемента. Нельзя было выбрать родителя по ребёнку или предыдущего брата по
следующему. Причина — потоковый разбор и производительность: стиль элемента должен быть
вычисляем, когда разобрано то, что выше и раньше него. Именно поэтому `:has()` появился только
в 2022–2023 годах.

Текстовые узлы и комментарии комбинаторы **не видят**: «соседний» — значит соседний **элемент**.

## 5. Псевдоклассы: обзор

**Псевдокласс** (pseudo-class) — условие, которого нет в разметке как атрибута: состояние, положение
в дереве, взаимодействие. Записывается через одно двоеточие. Подробно они разобраны в курсе
[Псевдоклассы](LEARN_CSS_PSEUDO_CLASSES_COURSE.md); здесь — карта.

| Группа | Примеры | Что проверяют |
|---|---|---|
| взаимодействие | `:hover`, `:active`, `:focus`, `:focus-visible`, `:focus-within` | действия пользователя |
| ссылки | `:link`, `:visited`, `:any-link`, `:target` | состояние ссылок и якоря в адресе |
| формы | `:checked`, `:disabled`, `:required`, `:invalid`, `:user-invalid`, `:placeholder-shown` | состояние полей |
| структура | `:first-child`, `:last-child`, `:only-child`, `:nth-child(2n+1)`, `:nth-of-type()`, `:empty`, `:root` | положение в дереве |
| язык и направление | `:lang(ru)`, `:dir(rtl)` | язык и направление текста |
| логика | `:is()`, `:where()`, `:not()`, `:has()` | комбинации других селекторов |

Тонкость `:nth-child(An+B)`: `n` пробегает 0, 1, 2…; подходят позиции (с 1), равные `An+B`.
`:nth-child(3n+1)` → 1, 4, 7; `:nth-child(-n+3)` → первые три; `odd` = `2n+1`, `even` = `2n`.
Форма `:nth-child(2n of .item)` считает только элементы, подходящие под `.item`.

`:nth-child` считает **всех братьев-элементов**, `:nth-of-type` — только братьев того же типа.
`p:first-child` не выберет первый абзац, если перед ним стоит `h2`.

Псевдоэлементы (`::before`, `::marker`) — это не условия, а **выбор части** или **созданного
содержимого**; они пишутся через два двоеточия, в сложном селекторе стоят последними и разобраны в
курсе [Псевдоэлементы](LEARN_CSS_PSEUDO_ELEMENTS_COURSE.md). Старые четыре (`:before`, `:after`,
`:first-line`, `:first-letter`) допускают одно двоеточие ради совместимости с CSS2.

## 6. Логические псевдоклассы

### 6.1. `:is()` и `:where()`

Оба принимают список селекторов и подходят, если подходит **любой** из них. Сокращают
комбинаторный взрыв:

```css
/* без :is — шесть селекторов */
article h1, article h2, article h3, aside h1, aside h2, aside h3 { … }
/* с :is — один */
:is(article, aside) :is(h1, h2, h3) { … }
```

Отличия:

| | `:is()` | `:where()` |
|---|---|---|
| специфичность | самого специфичного аргумента | **всегда 0** |
| список аргументов | прощающий (forgiving) | прощающий |
| зачем | краткость | базовые стили, которые легко перебить |

**Прощающий список** игнорирует неверные селекторы внутри, вместо того чтобы отбрасывать всё
правило. `:is(.a, :unknown)` работает как `.a`.

Ловушка специфичности `:is()`: `:is(#nav, .menu) a` весит как `#nav a` **даже для элементов внутри
`.menu`**, потому что вес — максимальный по списку, а не того аргумента, который совпал.

### 6.2. `:not()`

`:not(список)` подходит, если **ни один** аргумент не подходит. В Selectors 4 принимает сложные
селекторы и списки: `:not(.a, .b)`, `:not(nav a)`. Специфичность — как у самого специфичного
аргумента. Список у `:not()` **не прощающий**: одна ошибка — и правило отброшено.

Частая ошибка — думать, что `:not(.dark) p` значит «абзацы не внутри `.dark`». На деле это «абзац,
у которого есть **хотя бы один** предок без класса `.dark`», а такой предок есть всегда (`html`).
Правильно: `p:not(.dark p)`.

### 6.3. `:has()` — условие на потомков и соседей

`A:has(B)` подходит элементу A, если относительно него находится B. Аргумент — **относительный
селектор**: он может начинаться с комбинатора.

```css
figure:has(figcaption)  { }   /* figure, внутри которого есть подпись */
li:has(> ul)            { }   /* пункт с вложенным списком (ребёнок) */
h2:has(+ p)             { }   /* заголовок, за которым сразу идёт абзац */
form:has(:user-invalid) { }   /* форма с ошибочным полем после ввода */
body:has(dialog[open])  { overflow: hidden; } /* состояние всей страницы */
```

Свойства:

- специфичность — как у самого специфичного аргумента;
- список аргументов **не прощающий** (был прощающим в ранних версиях, это изменили);
- `:has()` нельзя вкладывать в `:has()`, и псевдоэлементы внутри не допускаются.

`:has()` превратил CSS из языка «смотрю вверх» в язык, где родитель знает о детях. Браузеры
сделали его быстрым кэшированием и ограничением инвалидации, но `:has()` у корня (`:root:has(...)`,
`body:has(...)`) при частых изменениях DOM всё равно заставляет перепроверять много элементов.

## 7. Пространства имён

CSS происходит из мира XML, где у элементов бывают **пространства имён** (namespaces). В HTML
элементы живут в пространстве XHTML, а `<svg>` и `<math>` внутри HTML — в своих. Обычно это
незаметно, но иногда важно: и в HTML, и в SVG есть элемент `a`.

```css
@namespace svg url(http://www.w3.org/2000/svg);

a       { color: teal; }        /* a из любого пространства (если нет пространства по умолчанию) */
svg|a   { fill: crimson; }      /* только a из SVG */
*|a     { }                     /* a из любого пространства явно */
|a      { }                     /* a без пространства имён */
```

`@namespace` должен стоять после `@charset` и `@import`, но до остальных правил. Если объявить
пространство **по умолчанию** (`@namespace url(http://www.w3.org/1999/xhtml);`), селекторы типа без
префикса будут подходить только элементам этого пространства. Селекторы классов, id и атрибутов
без префикса пространства не ограничиваются. На практике `@namespace` встречается редко, но
знать, что значит `svg|a`, нужно, чтобы не принять `|` за опечатку.

## 8. Специфичность

### 8.1. Тройка (A, B, C)

**Специфичность** (specificity) — вес селектора в каскаде. Это тройка чисел:

- **A** — количество селекторов id;
- **B** — классы, атрибуты, псевдоклассы;
- **C** — селекторы типа и псевдоэлементы.

Не учитываются: `*`, комбинаторы, `:where()` целиком. Особые псевдоклассы `:is()`, `:not()`, `:has()`
вносят вес **самого специфичного аргумента**. `:nth-child(An+B of S)` весит как псевдокласс
(0,1,0) **плюс** самый специфичный селектор из `S`.

Сравнение — **по разрядам слева направо**, как у версий программ: (1,0,0) больше, чем (0,99,99).
Никаких «переносов»: сто классов не перебьют один id.

### 8.2. Таблица расчётов

| Селектор | A | B | C | Пояснение |
|---|---|---|---|---|
| `*` | 0 | 0 | 0 | универсальный не весит |
| `li` | 0 | 0 | 1 | тип |
| `ul li` | 0 | 0 | 2 | два типа, пробел не весит |
| `ul > li + li` | 0 | 0 | 3 | комбинаторы не весят |
| `.nav` | 0 | 1 | 0 | класс |
| `[type="text"]` | 0 | 1 | 0 | атрибут = класс |
| `a:hover` | 0 | 1 | 1 | псевдокласс + тип |
| `p::first-line` | 0 | 0 | 2 | псевдоэлемент = тип |
| `#main` | 1 | 0 | 0 | id |
| `#main .nav a:hover` | 1 | 2 | 1 | |
| `:where(#main) a` | 0 | 0 | 1 | `:where` обнуляет |
| `:is(#main, .nav) a` | 1 | 0 | 1 | максимум по списку |
| `a:not(.x, #y)` | 1 | 0 | 1 | максимум по списку |
| `ul:has(> li.active)` | 0 | 1 | 2 | `ul` + вес `li.active` |
| `li:nth-child(2n of .item)` | 0 | 2 | 1 | псевдокласс + `.item` + `li` |
| `.a.a.a` | 0 | 3 | 0 | повтор класса законно повышает вес |

Атрибут `style=""` не имеет специфичности: он побеждает на отдельном, более раннем шаге каскада.
`!important` — тоже не специфичность, а уровень важности.

<summary>Специфичность против порядка: угадайте цвет</summary>

  /* Порядок специально перемешан: побеждает вес, а не место */
  #box .t                 { color: seagreen; }   /* (1,1,0) */
  :is(#box, .wrap) p      { color: crimson; }    /* (1,0,1) */
  .wrap p.t               { color: navy; }       /* (0,2,1) */
  :where(#box) p.t        { color: darkorange; } /* (0,1,1) */

  <div id="box" class="wrap">
    <p class="t" id="x">purple: (1,1,1)</p>

    <p>crimson: (1,0,1)</p>
  </div>

### 8.3. Как управлять весом

- Держите специфичность **низкой и ровной**: один-два класса на правило.
- Базовые стили — через `:where()`, чтобы любой класс их перебивал.
- Нужно поднять вес без id — повторите класс: `.btn.btn`.
- Нужно стилизовать по id без веса id — `[id="main"]`.
- Порядок слоёв надёжнее, чем гонка весов: `@layer reset, base, components;` — подробно в
  [Каскад и специфичность](LEARN_CSS_CASCADE_COURSE.md).

## 9. Как браузер проверяет селекторы: справа налево

### 9.1. Почему справа

Задача браузера при вычислении стилей — для **каждого элемента** найти подходящие правила. Возьмём
`nav ul li a`. Если читать слева направо, пришлось бы для каждого `nav` перебирать всех потомков в
поисках `ul`, затем `li`… Читая **справа налево**, браузер берёт элемент, проверяет самую правую
часть — **ключевой селектор** (key selector) `a` — и для большинства элементов сразу получает «нет».
Только для ссылок он поднимается по предкам: есть ли `li`, выше него `ul`, выше `nav`.

Подъём по предкам дешёв: у элемента один родитель. Спуск к потомкам — дорог: их может быть
тысячи.

### 9.2. Хэши правил и фильтр Блума

Браузеры не перебирают все правила для каждого элемента. Правила раскладываются по корзинам по
ключевому селектору: по id, по классу, по типу, «прочие». Элементу с `class="btn"` и тегом `a`
достаются только корзины `.btn`, `a` и универсальная. Затем для подъёма по предкам используется
**фильтр Блума** (Bloom filter) с хэшами id, классов и тегов предков: он за одну проверку говорит
«`nav` среди предков точно нет», и дорогой подъём пропускается.

### 9.3. Мифы о производительности

| Утверждение | Правда |
|---|---|
| «`*` медленный, никогда его не используйте» | `*` в ключевой позиции (`.menu *`) действительно подходит каждому элементу и проверяется для всех. `* { box-sizing }` — одно дешёвое правило. Дорого не `*`, а широкий ключевой селектор с длинной цепочкой. |
| «Глубина вложенности убивает производительность» | Благодаря фильтру Блума и корзинам реальная разница между `.a .b .c` и `.c` на типичной странице — микросекунды. |
| «id быстрее класса» | Оба попадают в хэш-корзину; разница несущественна. Вес id — гораздо большая проблема, чем скорость. |
| «Селекторы атрибутов медленные» | Современные движки проверяют их быстро; `[class~="x"]` не медленнее заметно, чем `.x`. |
| «`:has()` нельзя использовать» | Можно. Дорог он при частых изменениях DOM, когда стоит у корня или с широким аргументом. |

Где действительно теряется время — не в сопоставлении одного селектора, а в **инвалидации**
(invalidation): сколько элементов надо перепроверить при изменении класса или DOM. Смена класса у
`body`, от которого зависят селекторы `body.dark .x`, перепроверяет всё поддерево. Это нормально
для переключения темы раз в минуту и плохо для анимации каждый кадр. Измеряйте во вкладке
Performance («Recalculate Style»), прежде чем оптимизировать. Подробнее — в
[Производительность CSS](LEARN_CSS_PERFORMANCE_COURSE.md).

## 10. Селекторы в JavaScript — тот же язык

`querySelector`, `querySelectorAll`, `matches`, `closest` принимают **тот же** синтаксис. Ошибка в
селекторе бросает `SyntaxError` — в отличие от CSS, где правило просто тихо отбрасывается.

## Итог

- Селектор строится из простых → составных → сложных (через комбинаторы) → списков.
- Атрибуты: `=`, `~=`, `|=`, `^=`, `$=`, `*=` и флаги `i`/`s`; `.x` равно `[class~="x"]`.
- Комбинаторы смотрят только вверх и назад; `:has()` впервые позволил смотреть вниз и вперёд.
- `:is()` и `:not()` и `:has()` весят как самый специфичный аргумент, `:where()` — ноль; прощающие
  списки только у `:is()` и `:where()`.
- Специфичность (A,B,C) сравнивается по разрядам; `*` и комбинаторы не весят; `style=""` и
  `!important` решаются на других шагах каскада.
- Браузер проверяет селектор справа налево, с корзинами правил и фильтром Блума. Дорогая часть —
  инвалидация, а не длина селектора.
