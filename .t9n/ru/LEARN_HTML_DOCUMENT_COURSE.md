# Документ HTML: дерево, парсер, `<head>` и первый селектор

> Курс 1 из программы. Предыдущих знаний не нужно, но поблажек тоже не будет: с первой страницы
> мы говорим так, как говорят спецификации и браузеры. Каждое понятие вводится один раз и дальше
> используется без повторных объяснений.

**Что вы будете понимать после курса**

- что браузер на самом деле получает и во что это превращает;
- что такое **дерево документа** и почему HTML — это не «текст с тегами», а описание дерева;
- зачем нужна строка `<!doctype html>` и что ломается без неё;
- почему `<meta charset>` стоит **раньше** `<title>`;
- что такое **селектор** — главное понятие всей связки HTML + CSS + JavaScript.

---

## 1. Что приходит в браузер

С сервера (или с диска) приходит не «страница», а **последовательность байтов**. Браузер проходит
четыре шага, и почти каждая «странность» HTML объясняется одним из них:

| Шаг | Вход | Выход | Что может пойти не так |
|---|---|---|---|
| 1. Декодирование | байты | символы | неверная кодировка → «кракозябры» |
| 2. Токенизация | символы | токены: «открывающий тег `p`», «текст», «комментарий» | `<` в тексте читается как начало тега |
| 3. Построение дерева | токены | **DOM** — дерево узлов | незакрытые теги «чинятся» по правилам |
| 4. Отрисовка | DOM + CSS | пиксели | (курс 3) |

Главный вывод: **HTML-файл — это рецепт построения дерева**. Отступы и переносы строк в файле
нужны людям. Браузеру важно только то, какое дерево получится.

## 2. Минимальный правильный документ

<details>
<summary>Минимальный документ</summary>

<a href="https://slnknrr.codeberg.page/ru/course/in-html/html-document.html#example-1">see preview & continue study</a>

```html
<!doctype html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Первая страница</title>
</head>
<body>
  <h1>Привет!</h1>
  <p>Это абзац.</p>
</body>
</html>
```

</details>

Разберём каждую строку. Порядок здесь не случаен.

### 2.1. `<!doctype html>` — переключатель режима

Это не тег и не элемент: в дереве он становится особым узлом `DocumentType`. Его единственная
современная задача — включить **режим стандартов** (standards mode).

Без него браузер включает **quirks mode** — режим совместимости со страницами 1990-х. В этом режиме,
например, процентная высота считается иначе, а таблицы не наследуют размер шрифта. Ошибки такого рода
трудно найти: страница не падает, просто «немного не так» выглядит.

Проверить режим можно из JavaScript: `document.compatMode` вернёт `"CSS1Compat"` (стандарты) или
`"BackCompat"` (quirks). История этого переключателя — в курсе
[История, quirks mode и странности](LEARN_HTML_HISTORY_QUIRKS_COURSE.md).

> Почему такая короткая запись? Раньше doctype ссылался на DTD — длинное описание грамматики SGML.
> Браузеры никогда эти DTD не читали, а только сравнивали строку со списком известных. HTML5 выбрал
> самую короткую строку, которая во всех браузерах включает режим стандартов.

### 2.2. `<html lang="ru">` — корень дерева

У дерева ровно один корень — элемент `html`. Атрибут `lang` нужен не для красоты:

- синтезатор речи выбирает по нему произношение;
- от него зависит перенос слов (`hyphens: auto` в CSS);
- он задаёт правила кавычек (`<q>`) и проверку орфографии;
- его видит селектор `:lang(ru)` — вот и первое знакомство с селекторами.

### 2.3. `<head>` и `<body>` — две ветви

- `head` хранит **метаданные**: данные о документе, которые не показываются как содержимое
  (кодировка, заголовок вкладки, стили, скрипты).
- `body` хранит **содержимое**: то, что видит пользователь.

Важная деталь парсера: эти элементы появятся в дереве **даже если их не написать**. Попробуйте:

<details>
<summary>Документ без html, head и body</summary>

<a href="https://slnknrr.codeberg.page/ru/course/in-html/html-document.html#example-2">see preview & continue study</a>

```html
<!doctype html>
<title>Без обёрток</title>
<p>Парсер сам создаст html, head и body.</p>
<script>
  // Выводим строение дерева: у каждого узла — имя и дети.
  document.body.insertAdjacentHTML('beforeend',
    '<pre>' + document.documentElement.outerHTML.replace(/</g, '&lt;') + '</pre>');
</script>
```

</details>

Парсер увидел `<title>` — этот элемент может жить только в `head`, значит, `html` и `head` открылись
неявно. Увидел `<p>` — это содержимое, значит, `head` закрылся и открылся `body`. Это правила
**режимов вставки** (insertion modes) из спецификации HTML. Они одинаковы во всех современных
браузерах, поэтому так писать *можно*. Но явные `head` и `body` делают структуру очевидной для людей,
поэтому мы их пишем.

### 2.4. `<meta charset="utf-8">` — почему он раньше `<title>`

Вернёмся к шагу 1. Чтобы превратить байты в символы, браузер должен знать **кодировку**. Он ищет её
так (упрощённо, по убыванию приоритета):

1. метка BOM в начале файла;
2. HTTP-заголовок `Content-Type: text/html; charset=utf-8`;
3. **предварительное сканирование** (prescan) первых **1024 байт** в поисках `<meta charset>`;
4. эвристика — угадывание.

Отсюда два жёстких правила:

- `<meta charset>` должен целиком поместиться в первые 1024 байта. Поэтому он стоит первым в `head`.
- До него не должно быть **не-ASCII** символов. Если `<title>Первая страница</title>` окажется выше,
  браузер может начать декодировать русский заголовок по неверной таблице. Встретив `meta` позже,
  он перезапускает разбор, а если уже поздно — показывает «Ð\x9fÐµÑ\x80...» во вкладке.

Именно поэтому порядок такой: **сначала то, что нужно для чтения документа, потом его содержимое**.
Тот же принцип в `<meta name="viewport">`. Он должен быть известен до первой раскладки, иначе
мобильный браузер разложит страницу на ширину около 980px, а потом «передумает».

### 2.5. `<meta name="viewport">` — ширина «экрана» для CSS

Без этой строки мобильный браузер притворяется широким экраном (около 980 CSS-пикселей) и уменьшает
результат. Тогда ни одно правило `@media (max-width: 600px)` не сработает: с точки зрения CSS экран
широкий. Подробно — в курсе [Адаптивность](LEARN_CSS_RESPONSIVE_COURSE.md).

### 2.6. `<title>` — заголовок вкладки

Обязательный элемент (документ без `title` не проходит валидацию). Его видят вкладка, закладки,
история браузера, поисковики и программы экранного доступа при переключении окон. Это не то же самое,
что `<h1>`: `title` — имя документа, `h1` — заголовок его содержимого.

## 3. Дерево и его словарь

Возьмём такой фрагмент:

```html
<body>
  <header>
    <h1>Сайт</h1>
  </header>
  <main>
    <p>Текст <em>важный</em></p>
  </main>
</body>
```

Он задаёт дерево (текстовые узлы из пробелов пока опустим):

```
body
├── header
│   └── h1 ─ "Сайт"
└── main
    └── p
        ├── "Текст "
        └── em ─ "важный"
```

Словарь, который понадобится в каждом следующем курсе:

| Термин | Пример из дерева |
|---|---|
| **узел** (node) | любой элемент, текст, комментарий |
| **элемент** (element) | узел, созданный тегом: `p`, `em` |
| **родитель** (parent) | `p` — родитель `em` |
| **дочерний** (child) | `header` и `main` — дети `body` |
| **соседи** (siblings) | `header` и `main` — соседи |
| **потомок** (descendant) | `em` — потомок `body` (на любой глубине) |
| **предок** (ancestor) | `body` — предок `em` |

Тег — это **запись в файле** (`<p>` и `</p>`). Элемент — **узел в дереве**, который запись создала.
Когда говорят «тег `p` красный», на самом деле имеют в виду элемент.

### 3.1. Пробелы — тоже узлы

Переносы строк и отступы между тегами становятся **текстовыми узлами**. Обычно их не видно: CSS
схлопывает пробелы. Но иногда они проявляются, например как зазор между элементами `inline-block`.
Это классическая загадка вёрстки, и разбирается она в курсе
[Нормальный поток и display](LEARN_CSS_DISPLAY_FLOW_COURSE.md).

<details>
<summary>Пробел между тегами — видимый зазор</summary>

<a href="https://slnknrr.codeberg.page/ru/course/in-html/html-document.html#example-3">see preview & continue study</a>

```html
<!doctype html>
<html lang="ru">
<head>
<meta charset="utf-8">
<style>
  span { display: inline-block; width: 60px; height: 40px; background: #4f46e5; }
</style>
</head>
<body>
  <p>С переносами строк (видно зазоры):</p>
  <span></span>
  <span></span>
  <span></span>
  <p>Без пробелов между тегами (зазоров нет):</p>
  <span></span><span></span><span></span>
</body>
</html>
```

</details>

### 3.2. Парсер чинит ошибки — по правилам

HTML никогда не «падает». Каждая ошибка разметки обрабатывается так, как предписывает спецификация.
Например, `<p>` не может содержать блочные элементы вроде `<div>`. Встретив `<div>` внутри открытого
`<p>`, парсер **закроет абзац сам**:

<details>
<summary>p не может содержать div</summary>

<a href="https://slnknrr.codeberg.page/ru/course/in-html/html-document.html#example-4">see preview & continue study</a>

```html
<!doctype html>
<html lang="ru">
<head>
<meta charset="utf-8">
<style>
  p { border: 2px solid #e11d48; padding: 4px; }
  div { background: #fde68a; }
</style>
</head>
<body>
  <p>Начало абзаца <div>блок внутри?</div> конец абзаца</p>
  <pre id="out"></pre>
  <script>
    // Смотрим, что получилось на самом деле: div оказался ПОСЛЕ p, а "конец абзаца" - вне рамки.
    document.getElementById('out').textContent = document.body.innerHTML.split('<pre')[0];
  </script>
</body>
</html>
```

</details>

Отсюда практическое правило: **исходник и DOM — разные вещи**. Отлаживайте то, что в инструментах
разработчика (вкладка Elements / Inspector), а не то, что в файле.

## 4. Атрибуты

Атрибут — пара «имя = значение» в открывающем теге: `<html lang="ru">`. Атрибуты дают элементу
настройки (`href` у ссылки), имена для поиска (`id`, `class`) и данные (`data-*`). Подробно о них —
в курсе [Атрибуты](LEARN_HTML_ATTRIBUTES_COURSE.md). Сейчас достаточно двух:

- `id` — **уникальное** имя элемента в документе;
- `class` — список **меток через пробел**. Одна метка может стоять у многих элементов, у элемента
  может быть много меток.

## 5. Селектор — главное понятие

Дерево построено. Теперь нам нужно **указывать на его части**: «покрась все абзацы», «найди кнопку
отправки», «спрячь элементы с меткой `hidden`». Для этого и существует **селектор** — шаблон, который
проверяется на каждом элементе дерева и либо совпадает с ним, либо нет.

Один и тот же язык селекторов используют и CSS, и JavaScript:

```css
/* CSS: селектор выбирает элементы, к которым применить объявления */
p { color: #334155; }
```

```js
// JavaScript: тот же селектор находит элементы в дереве
document.querySelectorAll('p');
```

Базовые формы, которые понадобятся с первого же стиля:

| Селектор | Совпадает с | Опирается на |
|---|---|---|
| `p` | всеми элементами `p` | имя элемента |
| `#main` | элементом с `id="main"` | атрибут `id` |
| `.note` | элементами, у которых в `class` есть метка `note` | атрибут `class` |
| `header h1` | `h1`, у которых **где-то выше** есть `header` | отношение предок → потомок |
| `ul > li` | `li`, чей **непосредственный** родитель — `ul` | отношение родитель → ребёнок |
| `:lang(ru)` | элементами, язык которых — русский (с учётом наследования `lang`!) | состояние элемента |

Обратите внимание на последнюю строку. `lang` написан только на `html`, но `:lang(ru)` совпадёт и с
`p` глубоко внутри: язык **наследуется по дереву**. Это первый пример того, что селекторы работают с
деревом, а не с текстом файла. Наследование стилей устроено похожим образом, но со своими правилами
(курс [Наследование](LEARN_CSS_INHERITANCE_COURSE.md)).

<details>
<summary>Один селектор — в CSS и в JavaScript</summary>

<a href="https://slnknrr.codeberg.page/ru/course/in-html/html-document.html#example-5">see preview & continue study</a>

```html
<!doctype html>
<html lang="ru">
<head>
<meta charset="utf-8">
<style>
  /* Отношение "предок -> потомок": только h1 внутри header */
  header h1 { color: #4f46e5; }
  /* Метка класса: все элементы с note */
  .note { background: #fef9c3; padding: 4px 8px; }
</style>
</head>
<body>
  <header><h1>Заголовок в header — синий</h1></header>
  <h1>Заголовок вне header — обычный</h1>
  <p class="note">Абзац с меткой note.</p>
  <p>Абзац без метки.</p>
  <p id="out"></p>
  <script>
    // Тот же язык селекторов, но теперь для поиска:
    const n = document.querySelectorAll('header h1').length;
    const m = document.querySelectorAll('.note').length;
    document.getElementById('out').textContent =
      `querySelectorAll('header h1') нашёл ${n}, '.note' — ${m}`;
  </script>
</body>
</html>
```

</details>

### 5.1. Как браузер проверяет селектор

Неочевидная, но важная деталь: составной селектор `header h1` браузер проверяет **справа налево**.
Сначала он берёт кандидатов `h1`, затем у каждого поднимается по предкам и ищет `header`. Так быстрее:
самая правая часть (её называют **ключевым селектором**) сразу отсекает почти все элементы. Поэтому
`.menu a` дешевле, чем `.menu *`: в первом случае кандидаты — только ссылки, во втором — каждый
элемент страницы.

### 5.2. Уже здесь есть стили — до вашего CSS

Откройте пример 1: у `h1` крупный жирный шрифт, у `body` отступ 8px по краям, у абзацев отступы
сверху и снизу. Вы этого не писали. Это **стили браузера** (user-agent stylesheet), тоже набор
правил «селектор + объявления», например `body { margin: 8px; }`. Ваш CSS спорит с ними по правилам
**каскада**. Об этом следующий курс.

## 6. Комментарии и что попадает в дерево

```html
<!-- Комментарий: тоже узел дерева (Comment), но не отображается -->
```

Комментарии попадают в DOM, их видно из JavaScript (`Node.COMMENT_NODE`). Поэтому сборка проектов в
этом репозитории вырезает их из готовых файлов: читателю исходника они нужны, браузеру нет.

## Итог

- HTML — рецепт **дерева**. Отлаживайте дерево (DOM), а не файл.
- `<!doctype html>` включает режим стандартов. Без него — quirks mode.
- `meta charset` первым: кодировку нужно знать до первого не-ASCII символа, в пределах 1024 байт.
- `head` — метаданные, `body` — содержимое. Парсер создаст их и сам, но мы пишем явно.
- **Селектор** — шаблон над деревом. Один язык для CSS и JavaScript, проверяется справа налево.
- Стили есть ещё до вашего CSS: это стили браузера.
