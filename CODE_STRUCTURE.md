# Структура кода: семантика имён папок

Тип верхней папки репозитория определяется **разделителем в её имени**.

| имя | пример | что это |
|---|---|---|
| без разделителя | `photo/`, `raster/`, `png/`, `ui/`, `ico/` | компоненты и настоящие примитивы: строительные блоки, из которых собираются приложения |
| через дефис `-` | `resume-app/`, `image-processor/`, `icon-creator/` | SPA, веб-приложения, PWA |
| через точку `.` | `reset.css/`, `browser.css/`, `bulma_like.css/` | самостоятельные мини-фреймворки и проекты |

## Без разделителя — компоненты и примитивы

Примитивы и компоненты лежат **только** в папках без разделителей, никогда в папках с точкой. Нынешние JS-библиотеки
(`photo/`, `raster/`, `png/`, `jpg/`, `zip/`, `ui/`, `crypto/`, …) уже соответствуют этому правилу и остаются как
есть. Такие папки не собираются в артефакты сами по себе: их модули попадают в сборку приложений по импортам.

## Через дефис — приложения

Веб-приложения уже названы через дефис, и сборка (`singlefile.js`) именно так их и находит: приложение — это
верхняя папка, в имени которой есть `-`. В приложении лежат страницы (`*.html`), модули приложения и NOTICE-файлы,
которые выбирают артефакты (`OFFLINE_NOTICE.md`, `SINGLEFILE_OFFLINE_NOTICE.md`, `SERVERLESS_NOTICE.md`,
`BACKEND_NOTICE.md`, `STANDALONE_NOTICE.md`, `ELECTRON_NOTICE.md`, см. `targets.js`).

Каждое приложение содержит `DEMO_NOTICE.md`. Его первая строка `# НАЗВАНИЕ` задаёт имя демо: CI собирает приложение
как одну offline-страницу и публикует её в репозиторий Pages по адресу `demo/<название-через-дефис>.html`
(`# RESUME BUILDER` → `demo/resume-builder.html`). В этот репозиторий демо не записывается.

## Через точку — мини-фреймворки и проекты

Папка с точкой — это самостоятельный проект, который можно взять целиком. Расширение после точки говорит, что это
за проект. Отдельные `.js`-проекты не делаются; делаются **`.css`-проекты** (CSS-фреймворки):

- `index.css` — сама реализация стиля на чистом CSS, без JS. Например, `reset.css/index.css` или вариант для
  конкретного окружения: `browser.css/safari2014.css`.
- `index.js` (если есть) — JS-часть фреймворка: находит используемые на странице стили и создаёт их по правилу
  упоминания (класс или атрибут упомянут → нужное правило генерируется).

Внутри такой папки не лежат примитивы, которыми пользуются другие части репозитория: общие блоки живут в папках без
разделителя.
