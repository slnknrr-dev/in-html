# durak/

The card game Durak as a data-driven library: rulesets (decks of any size with copies and custom cards, card rules,
game rules) as plain JSON, a pure rules engine, ready-made rulesets with exclusive variants, strategist bots, a game
notation with the entropy of the public course, public-knowledge tracking, player style analysis and the game
definition for [`rooms/`](../rooms/). Pure ES modules, no DOM: the same code runs in browsers, in Node (servers,
simulations) and inside bot searches. The application is [`durak-game/`](../durak-game/).

## Rulesets

A ruleset is JSON: `{ id, name, description, author, tags, exclusive, deck, rules, skin? }`. `name` / `description`
may be a string or `{ en, ru, … }`. `normalizeRuleset` fills every default, expands the deck into card
definitions (`defs`, each with `copies`) and computes `hash` — the first 8 hex digits of SHA-256 of the canonical
game-relevant content (names, texts and pictures excluded): two rulesets with the same hash play the same game.
`validateRuleset` returns `{ ok, errors: [{ path, msg }], warnings, ruleset, players }`.

### Deck

```js
deck: {
  colors: [{ id: 'red', name, css: '#c62828' }, …],             // default red, black
  suits:  [{ id: 'H', name: 'Hearts', symbol: '♥', color: 'red' }, …],
  ranks:  [{ id: 'A', name: 'Ace', label: 'A', value: 14 }, …],   // value orders the ranks; default 2…A and X (joker, 15)
  sets:   [{ ranks: ['6', …, 'A'] | 'all', suits: ['S', 'C', 'D', 'H'] | 'all', copies: 1 }],   // rank × suit cards
  cards:  [{ id: 'R*', name: 'Red joker', label, rank: 'X', suit, color: 'red', copies: 1, art, note, rules: { … } }],
}
```

Generated cards get the code `<rank><suit lower-case>` (`Ah`, `Td`); custom cards their own `id` (1–6 letters, digits,
`_`, `*`). Codes that repeat add copies, so mixed decks (2 × 36, 2 × 52) and decks of any size (114 in Bazaar) are just
copies. Physical cards are numbered (uids) in definition order. `art` is `{ kind: 'joker' | 'glyph' | 'image', glyph,
src }` (an uploaded picture as a data URL).

### Card rules

Per custom card (`rules`) or for every card matching a pattern (`rules.cardRules: [{ match, set }]`, applied first):

| key | meaning |
| --- | --- |
| `trump` | `'suit'` (trump when its suit is the trump suit, default), `'always'` (tier `tier`), `'never'` |
| `value` | comparison value (default: the rank's value) |
| `wild` | `'color'` / `'suit'` / `'any'`: counts as every rank of its colour / suit / the deck for throw-ins, multi-card leads and transfers, and is ignored when the uniformity of a transfer is checked |
| `rankAs` | extra ranks the card counts as |
| `beats`, `beatenBy` | matchers: extra relations (this card beats / is beaten by matching cards) |
| `beatsOnly`, `beatenOnlyBy` | matchers: restrictions (`{ none: true }` = never) |
| `noLead`, `noThrow`, `noTransfer`, `noDefend` | play flags (a hand holding nothing else may still lead) |
| `closesBout` | after it beats a card nothing more is thrown in |

A **matcher** is `{ id, rank, suit, color, trump, wild, custom, minValue, maxValue, not, any: [matchers], none }`
(values are one value or a list; every given field must match). The value `'='` means "the same as the card that owns
the rule", so `{ color: '=' }` on a joker is the joker's own colour.

Whether card *d* beats card *a* (under a trump suit): the restrictions (`noDefend`, `a.beatenOnlyBy`,
`d.beatsOnly`), then `beatRules` with `deny`, then the explicit relations (`d.beats`, `a.beatenBy`, positive
`beatRules`), then the standard comparison — a higher trump tier wins; in the same tier the same suit (or, for trumps
with `trumpCross`, any suit) and a higher value. `compile()` turns this into a D × D table per trump suit, so the
engine and the bots never evaluate rules during play. Throw-ins use a second table: two cards match when they share
a rank class (`rankGroups` merge ranks into one class) or a wildcard covers the other card.

### The colour joker, sentence by sentence

The user's joker is not special code; it is these general rules (`JOKER_RULES`): `wild: 'color'`, `beats: [{ color:
'=' }]`, `beatsOnly: { color: '=' }`, `beatenBy: [{ color: '=' }]`, `beatenOnlyBy: { color: '=' }`, rank `X`.

| the rule | mechanism | test |
| --- | --- | --- |
| it beats its colour and only its colour; it is beaten only by its colour | relations + restrictions with `'='`; trumps of the other colour cannot beat it, it beats trumps of its colour | `joker: …` relation tests |
| any card of its colour may be thrown in to it, including the joker; two jokers allow any card | `wild: 'color'` in the throw-in table; jokers share rank `X`, so the other joker matches, and then every card of both colours | `joker: two jokers open every card` |
| among equal cards it counts as the same card: with three aces it transfers, the second joker continues | `uniform()` ignores wildcards and requires each wildcard to match another card of the group | `joker: transfers three aces`, `…continues the transfer` |
| a non-uniform card of its colour thrown onto the first joker freezes the transfer on the defender | the table is no longer uniform (aces + a three); jokers themselves never break uniformity | `joker: transfer frozen` |
| a joker can be thrown onto any card of its colour and transfer from there (red card → red joker → red six → black six) | wildcard match in both directions; the six matches the joker, the black six the red six | `joker chain: …` |

### Game rules

| key | default | |
| --- | --- | --- |
| `minPlayers`, `maxPlayers`, `handSize` | 2, 6, 6 | the deck also limits players (`playerRange`) |
| `trump` | `'bottom'` | `'bottom'` (the open bottom card), `'random'` (a suit, no card), `'none'`, or a suit id |
| `eternal`, `eternalTier` | `[]`, 2 | suits that are always trump, above the drawn one (the open card is never one of them) |
| `trumpCross` | true | trumps of different suits of one tier compare by value |
| `trumpExchange` | false | the holder of the lowest trump may swap it for the open trump card |
| `first` | `'lowestTrump'` | or `'random'`, `'seat0'` |
| `throwIn` | `'all'` | `'neighbors'` (the defender's two neighbours), `'attacker'` |
| `boutLimit`, `firstBoutLimit` | 6, 5 | 0 = unlimited / same |
| `limitByHand` | true | never more unbeaten cards than the defender holds |
| `leadMulti` | true | several cards of one rank class may lead |
| `transfer`, `transferShow` | false, false | perevodnoy; transfer by showing a trump of the rank |
| `throwAfterTake` | true | attackers may add cards after the defender decided to take |
| `teams` | 0 | number of teams (seat *i* plays for team *i* mod *teams*); partners never attack or throw in on each other |
| `direction` | 1 | −1 = counter-clockwise |
| `pogony` | false | "epaulettes" for a durak who loses to the lowest rank |
| `rankGroups` | `[]` | `[['6', '9']]`: ranks that count as one for throw-ins and transfers |
| `beatRules` | `[]` | `[{ by, beats, same: null | 'suit' | 'color' | 'rank' | 'card', deny }]` |
| `cardRules` | `[]` | `[{ match, set }]` |

## Engine

`newGame(ruleset, { players, rng, first, deal, trumpSuit })` shuffles with an rng of [`prng/`](../prng/) (or takes a
given deck order for replays), deals round robin and picks the first attacker. States are plain JSON; `apply(state,
seat, action)` validates and returns `{ state, events, error }` without changing its input (`applyInPlace` for
searches). Actions: `{ type: 'lead', cards }`, `{ type: 'throw', cards }`, `{ type: 'beat', card, slot }`,
`{ type: 'transfer', cards, show? }`, `{ type: 'take' }`, `{ type: 'pass' }`, `{ type: 'swap', card }`.

A bout: the attacker leads; the defender beats each card, transfers (while nothing is beaten and the table stays
uniform) or takes; the eligible players throw in matching cards within the limits — throw-ins are allowed at any
time, also while the defender is still answering. A bout ends when every card is beaten (or the defender takes) and
no eligible player wants to add more: a pass counts until the player gets a new option, a player without options has
passed. `turn(state)` names whose decision the game waits for (the defender with unbeaten cards, else the first
thrower who has not passed); `actors(state)` everybody who may act now. Then everybody draws (the bout's first
attacker first, the defender last), players without cards leave once the stock is empty, and the last player holding
cards — or the last team — loses.

The public log (`state.log`, in every view) records `['L', seat, uids]` lead, `['+', seat, uids]` throw-in,
`['B', seat, uid, slot]` beat, `['T', seat, uids, show]` transfer, `['X', seat]` take, `['P', seat]` pass,
`['S', seat, given, got]` trump swap, `['/', took, defender]` bout end, `['D', seat, n, trumpUid]` draw, `['O', seat]`
out, `['E']` end. `viewOf(state, seat)` shows the own hand, every hand size, the table, the open trump card and the
log; a pass shows only that the player passed (the cards it could have thrown are private); at the end all hands and
the deal are open.

## Presets

Classic: **Podkidnoy** (36), **Perevodnoy** (36, transfers), **Podkidnoy 52** (neighbours throw in, up to 8),
**Jokers 54** (52 + the two colour jokers, transfers), **Double deck** (2 × 36), **Teams 2×2**, **With pogony**
(trump exchange + epaulettes), **Blitz 24** (nines to aces, five in hand, transfers).

Exclusives designed for this engine:

- **Twins** — a double 36-card deck where a card is beaten by its exact twin (`beatRules: [{ same: 'card' }]`);
  transfers, neighbours throw in: twins chase each other around big tables.
- **Two Crowns** — hearts are an eternal trump above the drawn one, but may never lead or transfer: a second trump
  suit that only protects.
- **Ring** — the ranks close into a cycle: a six beats the ace of its suit and that ace cannot beat it (a positive and
  a `deny` beat rule); sixes and nines are one rank class.
- **Chameleon** — 36 cards and two colour jokers; every jack is a wildcard of its suit: long transfer chains.
- **Bazaar 114** — 2 × 52 + four colour jokers + six gold specials: the Crown (`trump: 'always'`, tier 3: the highest
  trump, only jokers resist it), the Shield (beats any plain card, closes the bout, never leads or is thrown in), the
  Fool (a wildcard of every rank that cannot defend and is beaten by anything); eight in hand, up to ten players.

Balance was checked with the simulations below (every preset: no illegal move, no unfinished game; the constructor's
quick tournament reports the first attacker's durak rate against the fair share).

## Bots

A bot is a **profile**: traits (principles), skills (abilities), a targeting rule and a level.

| trait | effect |
| --- | --- |
| `aggression` | throw-in threshold, multi-card leads |
| `trumpThrift` | value of trumps while the stock lasts (0 = spends them for tempo) |
| `risk` | beats with valuable cards rather than taking; fear of throw-ins |
| `transferLove` | preference for transfers |
| `takeStrategy` | takes cheap piles early to keep strong cards |
| `speculation` | deal speculation: who will draw the open trump card after this bout |
| `cooperation` | positional flow: who attacks whom after the bout; partners |
| `chaos` | noise on the scores |

| skill (0–3) | ability |
| --- | --- |
| `counting` | 0 nothing · 1 the discard · 2 cards seen in hands · 3 everything incl. the open trump card |
| `inference` | Bayesian-style re-weighting of opponents' possible cards from behaviour: a take (probably nothing that beats), a pass (probably no matching rank), a beat with an expensive card (probably no cheaper one); evidence fades as players draw |
| `lookahead` | Monte-Carlo rollouts on close decisions over hands sampled from the inferred distribution |
| `endgame` | exact minimax with memo when the stock is empty and two players are left (repetitions count as a draw) |

Targeting: `none`, `leader` (fewest cards), `weakest` (most likely durak), `next` (whoever attacks it next). Levels:
Easy (blunders 25 %, skills capped at 1), Normal (8 %, cap 2, 6 samples), Hard (3 %, the template's skills, 10
samples), Expert (no blunders, every skill of the template one step deeper, 28 samples, the largest search budget) —
the template's principles (traits) stay the same at every level. `options.samples` overrides the Monte-Carlo samples. Search budgets are node counts, so a seed replays the
same bot decisions on every machine; the slowest Expert decision stays below about 0.3 s.

A decision: the public tracker rebuilds what everybody saw; counting and inference give a belief about every hidden
card; each legal move gets a score from card values (`power` = share of the deck a card beats under the trump), the
burden of holding cards at this stage, the pressure the bot wants on the defender (targeting, aggression, positional
flow), transfer risk, the chance that the defender can answer, and deal speculation; close decisions go to Monte-Carlo
rollouts; endgames to the exact search.

Templates (`TEMPLATES`, each with a summary and three principles): **Rookie** (mechanical), **Miser** (trump
conservation, strategic taking), **Blitz** (aggressive trump dumping), **Accountant** (exact counting and inference),
**Puppeteer** (deal speculation, sets neighbours against a target), **Hunter** (targets the leader), **Vulture**
(cements the weakest as the durak), **Gambler** (risk and transfer chains), **Ally** (cooperation, partners),
**Grandmaster** (everything). `profileOf('custom', { level, traits, skills, targeting })` builds any mix.

### Difficulty and interactions (method)

`node durak/sim.js all --games 600` plays on Podkidnoy 36 with worker threads (`botstats.js` records the date, the
reference and the numbers):

- **Calibration**: each template at each level against two references (Rookie, Hard) at a table of three, 600 games
  per cell. Seats rotate and every cell uses the same seeds (common random numbers), so differences come from the
  bots, not from the deals. The durak rate *p* becomes a rating `1500 + 400 · log10((1/p − 1) / 2)` (1500 = as good
  as the reference; +400 = ten times the odds of escaping).
- **Interactions**: template X (Normal) with template Y and one reference, against X with two references, the same
  deals. `delta` is the change of X's durak rate caused by Y; `specific` subtracts Y's average effect on everybody,
  leaving what Y does to X in particular. Positive values: Y disrupts X; negative: X plays well next to Y. The game's
  bot picker shows the strongest three of each.
- **Duels**: every pair head to head, two players, seats alternating.
- **Styles**: the decisions of each template (Hard) through `analysis.js`: the profiles a person's style is compared
  with.

## Notation (DGN) and entropy

One line per game, `;`-separated fields:

```
DGN1;r=jokers-54@0459842a;n=3;p=Ann,Boris~puppeteer.3,Clara~blitz.3;t=5h;f=2;m=2L9c 0BKc>9c 1+Ks 0B8h>Ks 2P / 0L4c 1T4h 2TR* …;s=seed:replay-1;x=D1
```

`r` ruleset id and hash · `R` the ruleset itself (deflate + base64url) for own rulesets · `n` players · `p` names (a bot
is `name~kind.level`) · `t` the open trump card (`:S` a trump suit without a card, `-` none) · `f` the first attacker ·
`m` moves: `<seat base 36><op><cards>`: `L` lead, `+` throw in, `B<card>><attacked>[@slot]` beat, `T` transfer, `V`
transfer by showing, `X` take, `P` pass, `S` trump swap, `/` beaten off, `//` picked up · `s` seed (seeded shuffles) or
`d` the deal (base64url uids; for CSPRNG games) · `x` result (`D<seat>` the durak, `=` draw, `P<n>` pogony) · `g` date.

`replay(parse(text))` rebuilds every position. With `s` or `d` the real hands are replayed and every move is checked;
without them the public course alone is replayed: a deal consistent with everything public is built on the fly
(unseen cards swap into the hand that shows them), so table, hand sizes and public knowledge are exact while the hidden
hands are placeholders. A record never needs the hidden hands to be read.

**Entropy** uses public information only — what the game revealed, never what is in somebody's hand:

- *Course entropy* Σ log₂ *b* over the decisions, where *b* is the number of different public moves the player could
  have made at that moment judging only by public knowledge (its known cards plus one card of every kind nobody has
  seen; +1 for taking or passing). It measures how specific the observed course of the game was: the number of bits
  a record of this game needs when every publicly possible move is equally likely. Per seat and per decision too.
- *Hidden entropy* H = log₂ of the number of ways the unseen cards can lie in the hands and the stock given the public
  hand sizes (a multinomial: log₂ U! − Σ log₂ kᵢ!). It falls as cards are revealed; *openness* is the share of the
  initial hidden entropy the play revealed.

Copies of a card are indistinguishable: knowledge is kept as a multiset of card kinds, so it never depends on which
physical copy a player picked (`public.js`).

## Player analysis

`observe(counters, view, seat, action)` records one decision; `features(counters)`: take rate, strategic takes (takes
although everything could be beaten), transfer rate, trump thrift, economy (cheapest beating card), throw-in rate,
multi-card leads, trump leads while the stock lasts, low leads. `compare(features, profiles)` ranks the bot templates
by weighted distance; `traitsOf` gives style badges; `gameSummary` + `ACHIEVEMENTS` (18) the achievements.

## Rooms

`game` (`game.js`) is the [`rooms/`](../rooms/) definition: `settings = { rulesetId | ruleset, skin, names, avatars }`
(the ruleset and the room's look travel to every client), views carry the ruleset hash (`hydrate(view)` puts the
registered ruleset back), events are the log entries as objects, bots are `BOT_KINDS` (every template and `custom`
with `options: { level, traits, skills, targeting }`).

## Tests

`node durak/test.js` (about 25 s; `--long` plays more): every preset validates; relations of the variants; each joker
sentence; the bout flow (throw-ins, passes, re-opened throwers, take, limits, teams, trump exchange, showing a trump,
the Shield); thousands of actions of random legal games on every preset (card conservation after every action, views
hide hands and pass details); bot games on every preset with every template and level (no illegal decision, every
game finishes), determinism per seed, the exact endgame; DGN round trips (seeded, from the deal, public course with the
same course entropy, embedded own rulesets); the multinomial; analysis; a local room game and a networked game through
`rooms/server.js` (password, invite, synced look, own ruleset, hidden hands).
