# site-studio — план архитектуры и миграции (ред. 2)

## 0. Решения пользователя

1. **Полный перенос.** Всё, что умеют landing-studio и knowledge-processor, переносится в site-studio.
   Читать форматы `lp-landing` и `kp-kb` site-studio не будет.
2. **Полная независимость.** site-studio не импортирует код из `landing-studio/` и `knowledge-processor/`, только из
   библиотек (папок без дефиса). Нужный код переносится и перерабатывается внутри `site-studio/`. Заглушек и
   перенаправлений нет. Старые папки остаются как есть: пользователь сам удалит их после оценки.
3. **Собственный формат `ss-site` v1.**
4. **Учётные записи на backend.** Два способа входа: пароль и ссылка из письма. Есть публичные страницы backend
   (регистрация, вход, восстановление доступа, профиль) и полная система учётных записей: роли, приглашения,
   блокировка, сессии. Роли и права реализуются через библиотеку `access/`.
5. **Четыре экспорта** (§3).
6. **Шаблоны** делятся на три группы с цветными метками режима и тегами модулей (§5).

## 1. Основа

- Рендер страниц: движок `doc/`. Оболочка редактора: `studio/` и `ui/app.js` по образцу barcode-studio. Строки на 7 языках.
- Маршрутизация и пререндер: `spa/`. Порталы: `portal/`. Права: `access/`. Сервер: контракт `hosting.js`, артефакты по `targets.js`.
- Перенос логики из старых приложений, всё переписывается под `ss-site`:
  - из landing-studio: блоки, темы, магазин, `requests` и `local:`, чат, коллекции, генератор backend, админка;
  - из knowledge-processor: дерево страниц, версии, слои, 451, вики-разметка, вики-блоки, annotated picture, поиск.

## 2. Модель `ss-site` v1

```js
{ format: 'ss-site', version: 1, id, name, group: 'kb'|'landing'|'backend', template,
  meta, langs, defaultLang, theme, output,
  pages: [{ id, slug, parent, order, title:{}, seo:{}, hidden, draft, layout, cats,
            access: 'public'|'members'|'role:<id>'|'secret', versions:[{ id, label, blocks }], layers }],
  chrome: { header:[blocks], footer:[blocks], menus:[{ id, items:[{ label, link, children }] }] },
  types: [{ id, name, fields:[schema/], list, page }],      // типовые сущности модулей: статья, товар, событие, объект…
  records: { [typeId]: [...] },                             // их значения; редактор значений в backend без конструктора
  shop, requests, auth: { login:['password','link'], signup, roles, grants, policy },
  publish: { store:'session'|'local'|'idb', basePath, urlStyle },
  layers, cats, kdf, salt, sealed, attachments }
```

Блоки списков (статьи, товары, события, объекты) берут данные из `records` своего типа. Поэтому в backend без
конструктора можно создавать новые статьи и товары, не трогая разметку.

## 3. Экспорты

| экспорт | что получается | редактирование на сайте |
|---|---|---|
| **backend + конструктор** | `backend.js` (`hosting.js`): страницы, API, учётные записи, роли, закрытые разделы, админка и сам редактор site-studio на `/_studio/` | всё: страницы, блоки, темы, меню, типы, записи, пользователи |
| **backend без конструктора** | то же, но вместо редактора на `/_admin/` открывается редактор значений | `records` (создание статей, товаров, событий по типам модулей), тексты и картинки блоков, медиа, пользователи, заявки, заказы; структуру и дизайн менять нельзя |
| **serverless** | статический сайт из многих файлов: страницы заранее отрендерены, `404.html` и `spa/notfound.js` ловят все адреса; вариант SPA (только `index.html` + `404.html`); состояние в session/local/IndexedDB; корзина; `local:` и https-эндпоинты пользователя; SEO-файлы | — |
| **offline** | один HTML-файл, `#/route`, `file://`, сетевого кода нет (`*.offline.js`), только `local:` | — |

Сайты, собранные в режиме backend, тоже получают артефакты BACKEND / BACKEND_SINGLEFILE / ELECTRON по `targets.js`.
У самого приложения site-studio есть NOTICE-файлы: SINGLEFILE_OFFLINE, SERVERLESS, BACKEND, ELECTRON.

### 4.3 Визуализация и интеграции

- **Визуализация сайта** (`diagram/`, Mermaid-синтаксис): в редакторе схема сайта строится из модели. Есть виды:
  - дерево страниц и разделов (flowchart или mindmap);
  - навигация и меню;
  - доступ: какие роли видят какие страницы;
  - потоки данных: формы, корзина, заказ → `local:`, эндпоинт или backend (метки 🟢🟡🔴);
  - ER-схема типов и записей;
  - пользовательский путь: journey от лендинга к заказу.

  Схему можно скачать как SVG или как исходник `.mmd`, вставить блоком «Схема» на страницу сайта, а также в README.
- **seo-kit** (переиспользование, а не переход в приложение): модули и панели seo-kit встраиваются в site-studio
  как вкладка SEO. Данные берутся прямо из модели сайта: страницы, языки, организация, записи.
  - Генераторы: sitemap с hreflang и разбиением, robots.txt с тестером правил, llms.txt и llms-full.txt,
    RSS/Atom/JSON Feed для статей, JSON-LD десяти видов, OG/Twitter-теги с lint, OG-карточка 1200 × 630.
  - Проверка готовых страниц сборки.
  - Формы сущностей (организация, local business, person, адрес, geo, профили) хранятся в `meta`, поля страниц — в `seo`.
  - Общий код выносится в `seo/`, если сейчас он лежит в `seo-kit/`. Тогда seo-kit и site-studio используют одни
    модули; поведение seo-kit не меняется.
- **readme-editor**:
  - экспорт serverless и backend кладёт `README.md` репозитория сайта: как опубликовать, список страниц, схема в
    Mermaid, бейджи (`badge/`), переменные окружения backend;
  - редактор README встроен в экспорт: вид split / visual / source и рендер GitHub / Codeberg, модули readme-editor (общий код выносится в библиотеки);
  - блок «Markdown / README» показывает GFM с математикой, диаграммами, подсветкой и alerts тем же рендером, что
    у readme-editor;
  - импорт `README.md` или папки `.md` создаёт страницы: заголовки превращаются в разделы, ссылки на `.md` — в
    маршруты;
  - отдельный шаблон «Сайт проекта из README».

## 6. Структура

```
site-studio/
  model/ (site, pages, types, records, auth, check)   blocks/<группа>.js   runtime/   publish/ (offline, serverless,
  backend-site, backend-studio, backend-values, seo)   backend.js   admin/ (редактор значений)   ui/ (app.js…)
  templates/{kb,landing,backend}/   strings-{en,ru,uk,de,fr,es,ka}.js   e2e.js  test.js  NOTICE-файлы  README.md
```

CSS-классы получают префикс `ss-`, `ad-` не используется.

## 7. Этапы

1. Модель, типы и записи, нормализация, проверка режима (метка).
2. Рендер на `doc/`, перенос блоков лендинга и портала, меню и вложенные разделы, оболочка, offline-экспорт.
3. Serverless: `spa/`, 404.html, SPA-вариант, хранилища, корзина, `local:` и эндпоинты, SEO.
4. Вики: блоки, версии, слои, 451, поиск, annotated picture.
5. Backend: учётные записи (пароль и ссылка из письма), публичные страницы, роли, закрытые разделы, экспорт без конструктора (редактор значений).
6. Экспорт backend + конструктор, магазин с оплатой и заказами.
7. Новые блоки из §4.2.
8. Шаблоны из трёх групп с метками и тегами.
9. Визуализация сайта, встраивание модулей seo-kit и readme-editor (§4.3).
10. Документация, `ARCHITECTURE.md`, `README.md`. Старые `landing-studio/` и `knowledge-processor/` не трогаем.

Критерии готовности каждого этапа: `node check.js modules|tests|audit`; `node singlefile.js site-studio` собирает все
цели, в офлайн-сборках нет сетевого кода; e2e по четырём экспортам и магазину; скриншоты на десктопе и на 375 px.

## 9. Открытых вопросов нет

Старые приложения остаются нетронутыми: пользователь удалит их сам после оценки.

## 10. Состояние реализации (2026-10-25)

Сделаны все этапы 1–10. Проверки: `node check.js modules|tests|audit` проходят (site-studio: 150 + 124 вики-теста);
`node singlefile.js site-studio` собирает 4 цели, офлайн-сборка без сетевого кода; e2e редактора (десктоп и 375 px),
`e2e-modes.mjs` по пакетам: SPA с `404.html`, backend с учётными записями, магазин на backend, конструктор.

Отличия от плана:
- **Базы знаний — тоже `ss-site`** (сделано вторым шагом): вики-блоки, версии, слои и разделы 451 — блоки основного
  редактора, 9 вики-шаблонов собираются как сайты. Прежний редактор `wiki.html` (формат `ss-wiki`) оставлен рядом.
  Отличие от вики: 451 — это раздел страницы (контейнер), а не страница или вариант целиком; категории стали страницами.
- Типовые сущности модулей (`types` / `records` из §2) реализованы через «коллекции содержимого» — списочные блоки с
  полем `source`: в backend без конструктора админка создаёт и правит статьи, товары, объекты, номера, курсы.
- Префикс CSS-классов страниц остался `lp-` (движок `doc/`); новые блоки — `ss-`.
- Конструктор кладёт в пакет однофайловый редактор: в однофайловых сборках — сам себя, в многофайловых просит выбрать
  файл `html@5_offline_singlefile/index.html`.
- Бронирование считает цены сам (сезоны, выходные, занятые даты), библиотеку `booking/` не использует.

Известное: на ширине 375 px панели блоков и свойств оболочки `studio/` открыты поверх холста (так же в landing-studio).
